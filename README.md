### 4. `find` и `xargs`

```bash
find /tmp/pr12_level_a -type f -size +1M -mtime -1
find /tmp/pr12_level_a -type f -name '*.txt' -print0 | xargs -0 -r wc -c
```

```text
[Добавить настоящий вывод из Ubuntu]
```

`-type f`: только обычные файлы; `-size +1M`: файлы больше одной **единицы 1 MiB с округлением размера вверх** (т.е. не просто строго больше 1 MiB: файл 1 MiB+1 байт занимает 2 единицы); `-mtime -1`: дата модификации менее 24 часов назад; `-size -1M`: файлы с размером менее **одного блока единицы MiB после округления**, то есть фактически **пустые файлы** (размер 0), а не все файлы меньше 1 MiB. Для файлов 1–1048576 байт используйте `-size 1M`.

`-print0` и `xargs -0` безопасно обрабатывают пробелы и переводы строк в именах; `wc -c` считает байты для каждого текстового файла.

## Уровень B

### backup.sh

```bash
bash backup.sh backup /tmp/pr12_source /tmp/pr12_copy
bash backup.sh restore /tmp/pr12_copy /tmp/pr12_source
bash tests/b_tests.sh
```

Копируются только отсутствующие или отличающиеся **по размеру/ SHA-256** обычные файлы. `shutil.copy2` сохраняет права и времена на файлах; права/время каталогов копируются отдельно. Журнал — `.pr12_backup_journal.jsonl` в каталоге назначения. Повторный запуск не копирует неизменившиеся файлы. При restore существующий изменённый файл сохраняется под именем `имя.before_restore` (при конфликте — с числовым суффиксом). Копию внутри источника создавать запрещено. Символьные ссылки намеренно не копируются; это учебная реализация для обычных файлов.

### dedup.py

```bash
python3 dedup.py /tmp/pr12_duplicates
```

Программа обходит обычные непустые файлы и группирует кандидатов по устройству, длине, UID, GID, режиму прав и SHA-256. Для совпадающих файлов создаётся жёсткая ссылка, а старый файл заменяется атомарным `os.replace`. Уже связанные inode пропускаются. Программа выводит логический объём устранённых копий и ориентировочную экономию выделенных блоков (`st_blocks * 512`).

**Проверенный искусственный пример:** две копии текста по 18 байт: заменён 1 файл, устранено 18 байт логических дубликатов, оценка освобождённых блоков в тестовой ФС — 4096 байт. Это **локальный тест**, а не вывод эксперимента с Ubuntu.

Почему изменение «одной копии» меняет все: после дедупликации все имена ведут к **одному inode и одной последовательности блоков**. Изменение байтов файла на месте будет видно по всем именам; замена имени новым файлом (atomic replace) может разорвать эту связь.

### Модель размещения

| Способ | Блоков прочитать до k-го | Дописывание в конец | Внешняя фрагментация |
|---|---|---|---|
| Непрерывный | O(1), вычисление смещения | Требует свободного пространства непосредственно после экстента либо переноса/нового экстента | Возможна |
| Связанный | O(k), проход по цепочке | Относительно простое выделение нового блока, нужно обновить указатель | Как правило нет, но возможна рассеянность блоков |
| Индексный | O(1) для прямой одноуровневой таблицы индексов после чтения таблицы; для многоуровневой — дополнительные уровни | Добавление адреса блока в индекс, при заполнении таблицы нужны новые индексные блоки | Как правило нет |

## Контрольные вопросы

1. **Почему нельзя создать жёсткую ссылку на файл в другой файловой системе?** Жёсткая ссылка — это дополнительная запись каталога, указывающая на inode **той же файловой системы**. На другом устройстве эта inode-идентичность не распространяется; операция завершается `EXDEV`.
2. **Что физически удаляется при `rm`, если на файл есть две жёсткие ссылки?** Удаляется одна запись каталога и уменьшается счётчик ссылок inode. Пока остаётся другая жёсткая ссылка, inode и данные не освобождаются. После удаления последней ссылки и закрытия всех открытых дескрипторов файловая система может освободить inode и блоки.
